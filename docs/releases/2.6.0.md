# bazis-async-background 2.6.0

## Changes

- `GET /async_background_response/{task_id}/` returns the stored status of the task in the
  header `X-Task-Status` (`pending`, `processing`, `completed`, `failed`), also documented
  in the OpenAPI schema. The body `{"status": "not ready"}` could not be told apart from a
  stored response of the same shape; it stays as it was, a placeholder returned while the
  task has no response (also for a task completed without one). The error responses
  (401, 403, 404) do not carry the header. A browser client on another origin cannot read
  it (the CORS middleware of Bazis does not expose it): such a client polls with
  `?full_response=true`.
