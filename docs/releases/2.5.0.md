# bazis-async-background 2.5.0

## Removed

Nothing in the Bazis packages and the known products used them:

- `broker.ensure_topic_exists`, `broker.get_topics_by_prefix` and the settings
  `KAFKA_ADMIN_TIMEOUT_MS`, `KAFKA_AUTO_TOPIC_NUM_PARTITIONS` and
  `KAFKA_AUTO_TOPIC_REPLICATION_FACTOR`: no consumer command created topics with them.
  Create the topic with the tools of Kafka (or let the broker create it).
- `utils.set_and_publish_status`, the synchronous twin of `set_and_publish_status_async`,
  and the module-level synchronous client `utils.redis`: it connected to the cache at the
  import of the module in every process of the API (and failed with a cache that is not
  Redis). The tests read the statuses with `testing.redis_client()`.
- `broker.get_broker_for_async` (the publishing broker, not started): use
  `get_started_broker_for_async`.
- `TaskStatus.CREATED`: no task has had it since 2.3.0, a task is `pending` before it is
  published.
- `KAFKA_ACK_POLICY=reject_on_error`, deprecated in 2.3.1 as the same as `ack`: the setting
  now fails validation with it; set `ack`.

## Tests

- `bazis.contrib.async_background.testing`: the helpers of the tests of background tasks,
  shared with bazis-async-request: the hook that skips the tests marked
  `run_with_consumer` without Kafka settings, `wait_for_task`, `wait_for_tasks`,
  `redis_client`, `delete_tasks`.
- The Docker Compose stand of the tests (`sample/Dockerfile`,
  `sample/docker-compose.test.yml`, `sample/test.env`: Kafka 7.0 with ZooKeeper) is
  removed: the tests run as in CI, with a Kafka KRaft node (see `CLAUDE.md`).

## Upgrading

- Replace `KAFKA_ACK_POLICY=reject_on_error` with `ack` before the upgrade.
