# bazis-async-background 2.3.1

Requires bazis-ws 2.3.1.

## Changes

- `KAFKA_ACK_POLICY` is `ack` by default and accepts `ack` or `nack_on_error`.
  `reject_on_error` (the 2.3.0 default) is removed: in FastStream 0.7 it is the same as
  `ack` and emitted a warning on every consumer start. A project that set it must set `ack`.
- `kafka_consumer_multiple --max-restarts` counted the normal exits of consumers at the end
  of their lifetime (`KAFKA_CONSUMER_LIFETIME_SEC`), so consumers stopped for good after a
  number of lifetimes; only failures count now. A consumer that exceeded the restarts is no
  longer reported again on every poll.
- One registry of the publishing brokers per event loop instead of two;
  `get_started_broker_for_async()` returns the started broker of the running loop
  (`get_broker_for_async()` still returns it, not necessarily started).
  `drop_closed_loops` comes from bazis-ws.

## Tests

- The marker of the tests that need a consumer is `run_with_consumer` again, as in
  bazis-async-request (2.3.0 renamed it to `kafka`).
- CI migrates the database shared by the tests and the consumer and runs pytest with
  `--reuse-db`, as bazis-async-request does.
